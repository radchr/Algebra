# AGENTS.md — Інструкції та Архітектура Проєкту "Адаптація Кисельова"

## 1. Мета та огляд проєкту
Створення сучасної україномовної освітньої адаптації класичного підручника-задачника **А. П. Кисельова «Задачи и упражнения к элементам алгебры» (4-е видання, 1931 р.)**.

Оригінал підручника міститься у файлі `Zadachi i upr. k eliemientam al - Nievidomii.pdf` (118 сторінок сканованого тексту без текстового шару).

### 1.1. Поточний основний продукт (Digital-First у Marimo)

На цьому етапі **основною версією проєкту є інтерактивний цифровий курс у Marimo** (`app_geometry.py` та `app.py`). 
* Підготовка PDF та поліграфія **не потрібні**.
* Джерелом контенту є чисті, людинозчитувані файли Markdown у каталозі `content/geometry/*.md`.
* Геометрія базується на 3-рівневій системі:
  1. **`sympy.geometry`** — аналітичне ядро, розв'язувач та валідатор відповідей учня.
  2. **`drawsvg`** — генератор чистих векторних креслень у чистому Python (рендериться за 0.1 мс).
  3. **`JSXGraph`** — точкова тактильна пісочниця (пряме перетягування точок пальцем, суміщення фігур).
  4. **`marimo-studio`** — багатошарова архітектура представлень (Multi-View: чиста книга `textbook`, лабораторія `lab`, презентація `slides` з проекцією клітинок).
* Повні технічні деталі та специфікація зафіксовані в [`ARCHITECTURE_DIGITAL_GEOMETRY.md`](file:///c:/Users/taxco/Dev/Algebra/ARCHITECTURE_DIGITAL_GEOMETRY.md).

## 2. Ключові принципи та вимоги

### 2.1. Мова та локалізація
* **Мова видання:** лише українська. Двомовність (EN) скасовано: не додавати англійських полів, перекладів чи перемикача мов.
* **Термінологічна адаптація:** Заборонено калькувати застарілу радянську термінологію 1930-х років.
  - *«Алгебраическое знакоположение»* ➔ *«Алгебраїчні вирази та буквені позначення»*
  - *«Относительные числа»* ➔ *«Додатні та від'ємні (раціональні) числа»*
  - *«Составное именованное число»* ➔ *«Складене іменоване число»*
  - *«Расположенные многочлены»* ➔ *«Впорядковані многочлени (за спаданням/зростанням степенів)»*
  - *«Чертеж»* ➔ *«Креслення / Рисунок»*
  - *«Признаки равенства»* ➔ *«Ознаки рівності»*
  - *«Прилежащий угол»* ➔ *«Прилеглий кут»*

### 2.2. Математична точність та символьне ядро (SymPy CAS)
* Відповіді учня **не порівнюються як простий текст**.
* Для валідації використовується `sympy` та `sympy.geometry`:
  - Перевірка алгебраїчної еквівалентності: `simplify(user_expr - expected_expr) == 0`.
  - Підтримка різних допустимих форм запису (наприклад, `(x + 1)(x - 1)` і `x**2 - 1`).
  - Звірка з офіційним розділом відповідей підручника (сторінки 94–117 PDF Кисельова та відповіді задачника Рибкіна).

### 2.3. Дидактика та педагогіка (7 клас / STEM)
* Застосування підходу **POEM** (*Predict – Observe – Explain – Mission*) та 3-рівневих сократівських підказок (*Scaffolding*):
  1. **Рівень 1 (Концептуальний):** натяк на сутність ідеї (без формул).
  2. **Рівень 2 (Формульний):** натяк на потрібну формулу чи проміжний крок.
  3. **Рівень 3 (Повний розбір):** покроковий розв'язок у стилі Feynman (інтуїтивні моделі, без псевдонаукового слопу).

## 3. Технічний стек та інструменти

* **Менеджер пакетів:** `uv` (`pyproject.toml`, віртуальне оточення `.venv`).
* **Мова:** Python 3.11+.
* **Основний інтерфейс:** `marimo` — реактивні блокноти та веб-дашборди (`marimo run` / `marimo edit` / `marimo export html-wasm`).
* **Символьна математика:** `sympy` та `sympy.geometry`.
* **Векторна графіка:** `drawsvg` для швидкого генеративного шкільного SVG у Marimo.
* **Тактильні маніпулятиви:** `JSXGraph` через `anywidget` / `mo.Html`.
* **Мультимодальне розпізнавання (OCR + Translation):** `google-genai` (Gemini Flash / Pro Vision).
* **Лінтер та форматер коду:** `ruff` (`uv run ruff check .` та `uv run ruff format .`).

## 5. Правила для агента (Rules of Engagement)

1. **Digital-First у Marimo (Жива інтерактивна книга):** Основним артефактом є живий цифровий підручник Marimo без технічного шуму для дитини. Текст Кисельова подається повністю, без скорочень. Інтерактивні віджети (DrawSVG, JSXGraph), інтуїція Фейнмана та пастки мислення чергуються безпосередньо з текстом. Зона читання оптимізована: `max-width: 780px`, шрифт `19px`, `line-height: 1.75`.
2. **Трирівнева геометрія:** Математика рахується у `sympy.geometry`, креслення генеруються через `drawsvg`, складні динамічні рухи — через `JSXGraph`.
3. **Лише українська мова:** Кожна додана задача має поле `text_uk` та коректний LaTeX у `formula_latex`. Англійських полів і перекладів не створювати.
4. **Захист від слопу (`anti-slop`):** Пояснення повинні бути чіткими, лаконічними, без штучно нагромаджених термінів чи абстрактної "води".
5. **Перевірка розв'язків:** Кожна задача перед додаванням у продакшн-датасет повинна бути автоматично розв'язана і верифікована через SymPy.
6. **Цілісність коду Marimo:** Дотримуватися реактивного DAG: чисті допоміжні функції (`pure functions`) виносити в модулі `src/geometry_engine/` та `src/algebra_kiselev/`, а в клітинках Marimo тримати лише реактивний стан та візуальні елементи `mo.ui.*`.
7. **Повна автономність дій (Always Proceed / Zero Friction):** Агент зобов'язаний виконувати всі потрібні дії (створення/редагування коду, запуск тестів, виконання скриптів і команд git) самостійно і проактивно, не перепитуючи дозволу та не зупиняючи процес на підтвердження стандартних операцій.
8. **Не відволікатися на правові питання:** За замовчуванням не проводити правовий або ліцензійний аудит джерел. Повертатися до нього лише на прямий запит користувача.
9. **Контроль якості коду через Ruff:** Перед завершенням будь-якого етапу агент або розробник запускає:
   - `uv run ruff check . --fix` — перевірка та автоматичне виправлення помилок стилю та імпортів.
   - `uv run ruff format .` — приведення коду до єдиного стандарту форматування.
   - Специфіка реактивних файлів Marimo врахована у секції `[tool.ruff.lint.per-file-ignores]` файлу `pyproject.toml`.
10. **Суворе ігнорування заморожених треків:** Не чіпати, не рефакторити, не компілювати та не створювати нові файли у каталогах `book_geometry/`, `docs/`, `src/geometry_pipeline/`, архівних папках та модулях старої алгебри. Весь робочий фокус зосереджений виключно на `app_geometry.py`, `content/geometry/*.md`, `src/geometry_engine/` та `data/geometry/book_kb.db`.
11. **Принцип «Спочатку повний кеш — потім компонування» (Cache-First Two-Stage Pipeline):**
    Для будь-якого нового розділу чи порції підручника суворо дотримуватися правила двох фаз:
    - **Фаза 1 (Повний кеш у SQLite):** Заборонено починати верстку уроків у Marimo чи створення нових файлів у `content/geometry/` доти, доки 100% сторінок розділу не оцифровано та не верифіковано в таблиці `book_pages` (повний OCR, НУШ-переклад, інтуїція Фейнмана, пастки мислення) і 100% відповідних креслень не згенеровано та не збережено у векторному DrawSVG у таблиці `book_figures` з прив'язкою у `figures_json`. Кеш обов'язково верифікується тестами (валідний XML/SVG через ElementTree, зелений pytest).
    - **Фаза 2 (Інтерактивне компонування):** Збирання уроків у Marimo та Markdown відбувається виключно з готової локальної бази даних SQLite. Усі рисунки вставляються миттєво через `render_figure_card(fig_num)` або `get_book_figure_svg(fig_num)`. На етапі верстки неприпустимі звернення до VLM чи динамічний повторний розрахунок креслень (Zero Recomputation, 0 мс затримки).
