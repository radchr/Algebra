# 🤖 Marimo-Agent: Інженерно-дидактичний протокол підготовки дашбордів

Цей скіл описує протокол взаємодії AI-агента з екосистемою **Marimo** для проектування, генерації, валідації та полірування реактивних освітніх дашбордів і віртуальних лабораторій для 7 класу.

---

## 🧭 Дві ролі агента в Marimo

1. **Зовнішній агент-розробник (Antigravity / CLI Pair Agent):**
   - Створює структуру файлів, пише скрипти `.py` за стандартами реактивного DAG, запускає верифікацію через `uv run marimo check`, компілює у WASM HTML.
2. **Внутрішній асистент редактора (Marimo Copilot / In-Editor Agent):**
   - Працює безпосередньо у вікні браузера під час сесії `marimo edit` користувача, керуючись системними правилами з `marimo.toml`.

---

## 🔄 5-Етапний агентний пайплайн генерації дашборду

Коли користувач ставить завдання створити дашборд (наприклад, *"Зроби симуляцію сили тертя для 7 класу"*), агент проходить 5 обов'язкових кроків:

```
[ Крок 1. Концептуалізація теми за протоколом P-O-E-M ]
   ↓
[ Крок 2. Проектування реактивного графу залежностей (DAG) ]
   ↓
[ Крок 3. Генерація коду клітинок (Setup -> UI -> Engine -> View) ]
   ↓
[ Крок 4. Автоматична верифікація (marimo check & syntax validation) ]
   ↓
[ Крок 5. Перевірка працездатності в App Mode (marimo run) ]
```

---

## 📐 Крок 1. Дидактична декомпозиція за стандартом P-O-E-M

Кожен освітній дашборд для 7 класу **зобов'язаний** містити чотири фази:

1. **`Predict` (Прогноз):**
   - Питання-провокація на базі наївного уявлення (Misconception).
   - Елемент вибору: `mo.ui.radio` або `mo.ui.dropdown`.
   - *Мета:* Змусити дитину зафіксувати гіпотезу до початку маніпуляцій з повзунками.
2. **`Observe` (Дослід):**
   - Контролери введення з обов'язковими фізичними одиницями вимірювання (СІ): `кг`, `м/с`, `Н`, `г/см³`.
   - Інтерактивна візуалізація (Plotly або AnyWidget) за принципом **просторової суміжності Майєра**: стрілки сил і показники малюються прямо на об'єкті досліду.
3. **`Explain` (Пояснення & Деконструкція міфу):**
   - Зворотний зв'язок на прогноз: похвала за сміливість, пояснення, чому побутова інтуїція підвела.
   - Народження формули як короткого підсумку спостереження.
4. **`Mission` (Гейміфікований виклик):**
   - Чітка ігрова мета з пороговою перевіркою (наприклад: *«Налаштуй силу тяги так, щоб брусок рухався рівномірно зі швидкістю 2 м/с»*).
   - Візуальний бейдж успіху при виконанні умови.

## ⚙️ Крок 2 & 3. Стандарти кодування клітинок Marimo

### 1. Канонічна клітинка `setup` (Завжди перша!)
- Містить **лише імпорти бібліотек**.
- Не містить жодних змінних чи констант (це дозволяє Marimo оптимізувати гаряче перезавантаження клітин):

```python
@app.cell
def __():
    import marimo as mo
    import plotly.graph_objects as go
    import sympy as sp
    return go, mo, sp
```

### 2. Принцип розділення інтерфейсу та обчислень
- **Ніколи** не змішуйте створення UI-контролера та його використання в одній клітинці:
  - *Клітинка 1 (UI):* `mass_slider = mo.ui.slider(1, 10, value=2, label="Маса m (кг):")`
  - *Клітинка 2 (Calculation):* `weight = mass_slider.value * 9.8`
- Використовуйте `mo.ui.form()`, якщо параметрів більше 2-х, щоб запобігти безперервному джитеру розрахунків під час перетягування повзунка.

### 3. Двостороння інтеграція з JS (p5.js / D3.js) через `anywidget`
Якщо симуляція потребує тактильного перетягування (drag-and-drop важеля, частинок чи лінзи):

```python
import anywidget
import traitlets
import marimo as mo

class TactileSimulationWidget(anywidget.AnyWidget):
    # Синхронізовані змінні (Python <--> JavaScript)
    object_pos_x = traitlets.Float(0.0).tag(sync=True)
    is_colliding = traitlets.Bool(False).tag(sync=True)

    _esm = """
    function render({ model, el }) {
        const div = document.createElement("div");
        div.style.cssText = "width: 100%; height: 260px; background: #0f172a; border-radius: 12px;";
        // логіка малювання p5 або D3
        el.appendChild(div);
    }
    export default { render };
    """

widget_ui = mo.ui.anywidget(TactileSimulationWidget())
```

## ⚠️ Матриця підводних каменів (Gotchas) для агента

| Помилка агента | Що відбувається в Marimo | Як правильно робити |
|---|---|---|
| **Приватні змінні з `_`** | `_temp = 5` у клітинці А не видно в клітинці Б (`NameError`). | Використовувати звичайні імена `temp` для міжклітинного зв'язку, або об'єднувати логіку в одну клітинку. |
| **Повторне оголошення змінної** | `df = ...` у клітинці А та `df = ...` у клітинці Б викликає `Multiply-defined names`. | Кожна глобальна змінна повинна мати лише одну клітинку-власника. Для проміжних кроків використовуйте `_df_clean`. |
| **Дублювання імпортів** | `import numpy as np` у двох різних клітинках ламає валідацію. | Усі імпорти консолідувати виключно в першу клітинку `setup`. |
| **Читання `.value` при створенні** | `s = mo.ui.slider(1, 10); v = s.value` в тій самій клітинці. | Завжди виносити читання `s.value` в наступну дочірню клітинку DAG. |
| **Відступи в Markdown** | Відступ перед текстом у `mo.md("""  текст """)` сприймається як блок коду або викликає `warning[markdown-indentation]`. | Починати багаторядковий рядок `mo.md(r"""...""")` впритул без зайвих відступів всередині рядка. |

## 🧪 Крок 4 & 5. Автоматична перевірка агентом (CLI Checklist)

Після написання чи редагування будь-якого дашборду агент зобов'язаний виконати перевірку:

```bash
# 1. Статична перевірка графу залежностей Marimo:
uv run marimo check notebooks/physics/friction_lab.py

# 2. Якщо знайдено помилки — виправити їх негайно.

# 3. Перевірка експорту у автономний веб-додаток (WASM HTML):
uv run marimo export html-wasm notebooks/physics/friction_lab.py -o dist/friction_lab.html

# 4. Повідомити користувача про готовність та надати команду для запуску:
# uv run marimo run notebooks/physics/friction_lab.py --port 8080
```

## 🎨 Дизайн-код UI для 7 класу
- **Тема:** Темна `template="plotly_dark"` або графітова `#0f172a` (високий контраст, дружня до очей).
- **Кольори сил:**
  - Сила тяжіння / Вага: `#ef4444` (Червоний)
  - Сила Архімеда / Опора: `#38bdf8` (Блакитний)
  - Сила тертя: `#f59e0b` (Бурштиновий)
  - Сила тяги: `#22c55e` (Зелений)
- **Мова:** Бездоганна українська термінологія без кальок (наприклад: *«виштовхувальна сила»*, а не *«виштовхуюча»*; *«важіль»*, а не *«ричаг»*; *«сполучені посудини»*, а не *«сообщающієся»*).
